# Independent check: gitleaks vs GitSecure self-scan

Date: 2026-11-27. Question from Freddy: how can GitSecure's self-scan be
100/A — is the tool biased grading its own homework?

## Method

- Fresh clone of https://github.com/Squ1zM0/GitSecure at HEAD 57323998
  (42 commits) to /tmp/gs-gitleaks. Gitleaks 8.30.1 (latest release),
  default config, `--redact`, JSON reports.
- `gitleaks git` (full history) and `gitleaks detect --no-git`
  (working tree) — two separate runs, both exit 0 with reports.
- Compared against the live GitSecure self-scan the same day:
  100/A, wouldBeScore 0, 37 secrets (all likely-test-key), 0 vulns,
  0 posture. (Gitleaks only checks secrets, so it can only validate
  the secrets half — vulns/posture have no independent check here.)

## The one divergence — gitleaks false positive, not a GitSecure miss

Gitleaks' single finding is `generic-api-key` on the line:

```
check("Phase 13 repro: secrets deduction still 8", selfScan13.secretsDeduction === 8, ...);
```

Its Match is the English phrase `secrets deduction still 8`. There is no
credential on the line — it is a test assertion that a number equals 8.
GitSecure correctly does not flag it. This is gitleaks' generic rule
firing on a sentence containing the word "secrets", not a missed leak.

## Verdict

- Gitleaks found **nothing GitSecure missed**. No finding in production
  code, no finding outside test scripts/docs/fixtures, no real credential
  anywhere in the repo or its history.
- GitSecure is **more** sensitive than gitleaks here, not less: it flags
  36 things gitleaks' default config does not — 22 hardcoded-password
  assignments and 14 database URLs in test fixtures (e.g.
  `postgres://user:pass@host/db` in test data). Gitleaks' rules need a
  specific service format; GitSecure's generic detectors fire on the
  assignment shape alone.
- The AWS example key in README.md:96 (the well-known `AKIA...EXAMPLE`
  documentation key) is flagged by GitSecure as aws-access-key /
  likely-test-key; gitleaks allowlists it as the docs example. Both
  agree it is not real.
- The 100/A therefore survives an outside opinion on the secrets half:
  no outside scanner finds a secret GitSecure hid, and the only thing an
  outside scanner finds that GitSecure does not is a false positive.
  The 100 still rests on the two honest caveats in the report itself:
  triage verdicts (wouldBeScore 0 shown alongside) and the Phase 14
  fixture move. The score covers repo files only, not Vercel env vars,
  the GitHub token, or the Upstash token.
